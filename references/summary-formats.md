# 按内容组织总结

仅在需要总结时读这份说明。默认用对话语言，先一句话说明视频讲清了什么，再给最有用的几个要点。为主要要点标一个能回看上下文的时间戳（单 P 用 `00:12:34`，多 P 用 `P2 00:12:34`，按每 P 内时间）。用户没有要求字幕文件或诊断时，对话只给总结和必要的来源说明。

根据**核对过的字幕正文**判断主线，标题、简介和分 P 名只作线索。混合类型按用户关心的问题选结构；同一期访谈可以在相关段落解释一个机制，无需把整期硬分成两类。用户指定的用途、格式和详略优先；类型不明确时按主题归纳，别强行贴标签。

| 正文在做什么 | 总结怎么写 |
| --- | --- |
| 访谈、圆桌、播客：人物在回应问题、讲经历或辩论 | 按最重要的问题组织；写清谁给出了什么判断、理由或例子，有实质分歧就列出。多人发言归属不明时，不猜是谁说的。 |
| 科普、知识讲解：解释一个现象或概念 | 写清它要回答的问题、机制如何运作、视频用了什么证据或类比，以及哪些结论只在特定条件下成立。 |
| 故事、纪实、个人经历：事件和选择推动后续变化 | 交代起因、关键选择、转折和结果，区分真实事件与讲述者的解读。用户要求不剧透时，省略结局和关键反转。 |
| 教程、操作演示：教人完成一件事 | 先写能做到什么、需要什么，再按顺序给步骤、判断是否成功的方法和常见错误。画面中可能有字幕未提及的操作或参数，不从上下文猜填。 |
| 测评、比较：用若干维度评价不同选项 | 按测试条件和维度写差异，区分可观察结果与创作者偏好，指出结论适合哪类需求。 |

总结反映的是视频说了什么。对有争议或未经独立核实的主张，归到发言者或视频名下；不把创作者的推断写成事实。长视频可先给短概览，再列主题与定位；先读完整的可用字幕，再压缩成结论。只拿到部分分 P 时明确覆盖范围。
